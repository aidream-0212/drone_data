# drone-verify — 결과 검증 (커밋 · 제출 전)

## 실행 (drone-train → plan → evaluate → report 다음)
```powershell
python .claude/skills/drone-verify/scripts/verify.py          # 전체(재현성 포함, 약 1분)
python .claude/skills/drone-verify/scripts/verify.py --quick  # 재현성 제외
python scripts/check.py
```

## 검증 네 가지
| 구분 | 확인 | 왜 |
|---|---|---|
| A 재현성 | train · plan · evaluate를 다시 실행해 제출 · 점수 · 모델 정보 · 평가 · 모델 지문이 같은가 | 실행할 때마다 결과가 달라지면 보고서 숫자를 믿을 수 없다 |
| B 독립 대조 | 90일 고장 수 재계산 · 정답 재현 규칙 train 100% · 계획 적중 판정 = 정답 재현 · 시험 합계 = evaluate 드론 단위 합계 · 저장 결과 = 다시 계산 | 같은 값을 다른 길로 구해 같아야 계산 실수가 없다 |
| C 데이터 가정 | 같은 드론 · 같은 날 중복 0 · 이번 달 최근 기록 동점 0 · test/이번 달 드론 ⊂ train · 이번 달에 누수 컬럼 없음 · 고장 코드 결측 = 예방정비 | 코드가 깔고 있는 전제가 새 데이터에서 깨지면 결과가 조용히 틀린다 |
| D 결함 주입 | 이번 달 데이터 1칸(복사본) · 제출 확률 1개를 바꾸면 check.py 9 · 10번이 X, 복원하면 O | 점검 장치가 실제로 문제를 잡는지 확인한다 |

## 지킬 것
- 원본 `data/`는 바꾸지 않는다(결함 주입은 임시 복사본). 제출 파일은 백업 → 변경 → 반드시 복원한다.
- 실패 항목이 있으면 결과 파일을 손으로 고치지 말고, 원인을 먼저 보고한 뒤 해당 스킬을 다시 실행한다.
- 이 스킬은 '계산이 맞는가'를 본다. '예측이 맞았는가'는 drone-evaluate(2025 자체 평가 · 계획 적중 확인) 결과로 따로 말한다.
- 새 데이터(다음 달 기록 등)를 받거나 `drone_lib.py`를 고친 뒤에는 반드시 다시 실행한다.
- 출력과 `reports/verification.md`의 종합 줄을 그대로 보여 준다.
